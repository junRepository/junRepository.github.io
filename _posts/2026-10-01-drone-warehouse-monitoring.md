> 창고 지도에 그린 경로를 드론이 실제로 실행하고, 필요한 방향을 촬영한 뒤, 그 영상을 서버에서 확인할 수 있게 만드는 연구입니다. 저는 **경로계획·비행 실행·영상 촬영·서버 전송**을 담당했습니다.

| 항목 | 내용 |

| 검증 | 실제 창고의 경유점 비행, 통로 관측, 영상 저장·전송 기능 실증 |

이 글에서 소개하는 원문은 **국제학술대회 논문**입니다. 시스템은 산업 환경 안전관리를 위한 Eagle Eye System과 연계했습니다.

## 1. 배경: 실내 창고에서 필요한 관측을 수행하기

실내 창고에서는 GNSS/GPS 신호를 안정적으로 이용하기 어렵고, 선반과 구조물 때문에 관측 사각지대가 생깁니다. 드론을 활용하면 작업자와 물류 장비가 이동하는 통로를 관측할 수 있지만, 제한된 탑재 연산 자원으로 경로 실행과 영상 수집을 함께 처리해야 합니다.

이 연구에서는 사전에 확보한 **2D 레이아웃과 지정 경유점**을 활용했습니다. GUI에서 경로를 확인하고, 지도 좌표를 실제 이동 거리와 회전 명령으로 변환하는 구조입니다. SLAM을 경로 생성 과정의 필수 구성요소로 두지 않고, 알려진 지도와 정해진 운용 조건을 활용하는 접근입니다.

연구의 핵심 질문은 단순히 “경유점을 따라갈 수 있는가?”를 넘어, **“각 지점에서 필요한 통로를 촬영하고 결과를 모니터링 시스템에 전달할 수 있는가?”**였습니다.

## 2. 시스템 구성: 계획과 실행을 연결하는 데이터

전체 흐름은 다음과 같습니다.

```text
2D 창고 지도 + 선반·장애물 마스크
    → GUI에서 경유점과 방문 순서 지정
    → 픽셀 좌표를 실제 거리로 보정
    → 이동 거리·회전각·촬영 정보 구성
    → waypoint.json에 실행 데이터 저장
    → 비행 → 촬영 방향 회전 → 영상 촬영
    → API로 Eagle Eye System에 전송
```

지도에서는 이동 가능한 공간과 선반 영역을 구분합니다. 사용자는 경유점을 추가하거나 제거하면서 경로를 확인합니다. 경유점 좌표와 실행 정보를 JSON으로 저장해, 계획 단계와 비행 제어 단계가 같은 데이터를 사용하도록 연결합니다.

이 구조에서 지도는 경로를 정하는 기준이면서, 촬영 영상이 어느 위치의 관측 결과인지 연결하는 기준이기도 합니다.

## 3. 지도 좌표를 이동 거리와 회전으로 바꾸기

### 3.1 픽셀 간격과 실제 이동 거리는 다르다

GUI에서 얻은 좌표는 픽셀 단위입니다. 실제 공간의 길이에 맞추기 위해 `MAP_SIZE_COEFF`라는 픽셀당 거리 보정값을 사용합니다.

```text
scale = 실제 거리(cm) / 지도상의 거리(px)
pixel_distance = sqrt((x_next - x_now)² + (y_next - y_now)²)
travel_distance_cm = pixel_distance × scale
```

이 보정이 맞지 않으면 지도상으로 올바른 경로라도 실제 비행에서는 이동 거리가 달라집니다. 따라서 경유점의 위치뿐 아니라 지도의 축척과 좌표계 정렬을 함께 다루는 것이 중요합니다.

### 3.2 회전의 크기와 방향을 함께 계산한다

연속한 경유점에서 형성되는 벡터의 내적과 외적을 이용하고, `atan2`로 방향이 있는 각도를 계산합니다. 내적은 벡터 사이의 각도 관계를, 외적은 회전 방향을 표현하는 데 사용됩니다.

픽셀 좌표의 축 방향과 드론의 heading 기준은 서로 다를 수 있으므로, 계산한 각도를 비행 제어의 회전 명령과 일치시키는 과정이 필요합니다. 경유점 데이터의 좌표 기준과 제어 모듈의 회전 기준을 맞추는 것이 계획과 실행을 연결하는 핵심입니다.

## 4. 이동 방향과 촬영 방향을 구분하기

드론이 경유점에 도착해도 카메라가 통로를 향하지 않으면 모니터링에 필요한 영상을 얻기 어렵습니다. 따라서 경로를 따라 이동하는 방향과 관측 시점의 촬영 방향을 나누어 제어했습니다.

논문에 기술된 실행 절차는 다음과 같습니다.

1. JSON의 경유점 정보를 읽고 드론 연결과 비행 준비를 수행합니다.
2. 이륙 후 약 **300 cm** 고도로 이동합니다.
3. 다음 경유점을 향해 회전하고 지정된 거리를 이동합니다.
4. 촬영 위치에서 경로의 구간에 따라 **±90° 추가 회전**을 수행해 선반 사이 통로를 바라봅니다.
5. 경유점에서 약 **5초간 영상**을 촬영하고 저장·전송합니다.
6. 원래 이동 방향으로 복귀한 뒤 다음 경유점으로 진행합니다.
7. 마지막 경유점의 작업을 마치면 착륙합니다.

위 고도와 촬영 시간은 논문의 구현 조건입니다. 다른 창고나 기체에 그대로 적용하는 일반 운용값을 뜻하지 않습니다.

## 5. 실제 창고에서 확인한 결과

논문의 실험은 실제 창고에서 수행했습니다. 지도에서 비행 불가 선반 영역과 이동 가능한 영역을 구분하고, 작업자와 지게차가 이동하는 통로를 모니터링 대상으로 설정했습니다.

![실제 창고에서 촬영한 두 개의 선반 사이 통로 영상]({{ '/images/research/warehouse-corridors.png' | relative_url }}){: .research-figure-narrow }
*원문 그림 5, 논문집 p. 576. (a) 선반 1–2 사이 통로, (b) 선반 2–3 사이 통로의 관측 영상.*

원문은 다음 동작을 확인했다고 보고합니다.

| 확인 항목 | 실증 내용 |
| :--- | :--- |
| 경로 실행 | 지정 경유점에 따른 전진·회전 동작 수행 |
| 관측 방향 | 경유점에서 추가 회전해 선반 사이 통로 시야 확보 |
| 영상 수집 | 실험 창고의 두 통로를 촬영 |
| 데이터 연계 | 촬영 영상을 저장하고 서버로 전송 |
| 모니터링 | Eagle Eye System에서 지도와 연계된 영상 확인 |

이 결과는 **시스템 기능이 연결되어 동작하는지를 확인한 정성적 실증**입니다. 원문에는 위치 오차의 평균·분산, 전송 지연, 반복 비행 성공률, SLAM 대비 연산량의 정량 비교가 제시되어 있지 않습니다. 따라서 “정확도가 몇 % 향상됐다”거나 “연산량이 몇 % 줄었다”는 성과로 확장해 표현하지 않습니다.

## 6. 내가 담당한 부분과 연구의 의미

기존 포트폴리오에 기록한 담당 범위는 **드론 경로계획, 비행 실행, 영상 촬영 및 서버 전송**입니다. 이 논문에서는 제1저자로 참여했습니다.

제 담당 범위를 중심으로 보면, 이 연구의 의미는 경로계획의 출력이 실제 모니터링 작업으로 이어지도록 연결한 데 있습니다. 지도상의 경유점을 실행 가능한 이동량으로 바꾸고, 관측 지점에서 촬영 방향을 맞추며, 수집한 영상을 위치와 함께 확인할 수 있는 흐름을 구성했습니다.

Eagle Eye System 전체를 단독 개발했다는 의미는 아닙니다. 공동 연구 시스템 안에서 드론 기반 모니터링에 필요한 계획·실행·데이터 전달 부분을 담당했습니다.

## 7. 한계와 다수 로봇 연구로의 확장

이 접근은 사전 지도와 지정 경유점, 정해진 비행 조건을 활용합니다. 창고 배치 변화, 위치 추정 오차의 누적, 동적 장애물에 대한 대응까지 이 실험만으로 검증된 것은 아닙니다. 이를 확인하려면 위치 오차, 반복 운용, 전송 지연과 환경 변화에 대한 추가 평가가 필요합니다.

논문에서는 다수 드론을 이용한 커버리지 최적화, 객체 인식과 작업자 이동 경로 예측의 연계를 향후 방향으로 제시했습니다. 제 연구에서도 단일 드론의 실행과 관측 문제를 넘어, **여러 로봇에 작업을 나누고 센서 관측 범위에 맞춰 경로를 생성하는 문제**로 관심을 확장했습니다.
